# Разработка плагинов MTN2

> **Роль документа:** справочник автора плагина – что лежит в каталоге плагина, что описывает манифест, какие точки расширения есть у хоста и как плагин может заменить встроенную функцию.
> **Связанные документы:** [PLUGIN_BOUNDARIES.md](PLUGIN_BOUNDARIES.md) (что остаётся в ядре), [ARCHITECTURE.md](ARCHITECTURE.md) §6 (правила и устройство швов), [DIALOG_PLUGIN.md](DIALOG_PLUGIN.md) (формат диалогов).

---

## 1. Каталог и манифест

Плагин лежит в `plugins\<id>\` рядом с `MTN2.exe`: одна DLL (нативный плагин), либо `*.wasm` / `*.wat` (WASM-плагин) и необязательный `plugin.json`. Идентификатор плагина – имя каталога.

``json
{
  "id": "mtn.example",
  "name": "Example",
  "version": "0.1.0",
  "abi": 2,
  "schemes": ["example"],
  "archiveExtensions": ["exm"],
  "overrides": ["sftp", ".zip"],
  "startup": true
}
``

| Поле | Назначение |
|---|---|
| `abi` | Версия ABI, под которую собран плагин (1–4). Хост грузит плагины с ABI от 1 до своей версии |
| `schemes` | Схемы URI, которые плагин регистрирует. Плагин загружается при первом обращении к такой схеме |
| `archiveExtensions` | Расширения файлов, которые по Enter открываются как архив через первую схему из `schemes` (по умолчанию `7z`) |
| `overrides` | Встроенные обработчики, которые плагин просит заменить: схема (`sftp`) или расширение с точкой (`.zip`). Действует только по разрешению пользователя, см. §3 |
| `wasi` | `true` – WASM-модуль собран под WASI (Go, Rust с WASI-рантаймом). Хост даёт ему пустой WASI preview1: без файлов, окружения и аргументов, с увеличенным пределом памяти, и вызывает `_initialize` у модуля-реактора. Без этого поля модуль, импортирующий WASI, не загружается |
| `memoryMib` | Предел памяти WASM-модуля без WASI, в МиБ (до 256); без поля – 1 МиБ. Нужен модулю с большими таблицами, например библиотеке синтаксисов |
| `keepLoaded` | `true` – нативная DLL остаётся в памяти после выгрузки или отключения плагина: регистрации снимаются и `mtn_plugin_shutdown` вызывается, `FreeLibrary` – нет. Нужно DLL с рантаймом, который нельзя остановить (Go) |
| `description` | Что плагин делает и как им пользоваться: строка или объект по языкам (`{"en": "...", "ru": "..."}`); без своего языка берётся английский |
| `author`, `homepage` | Автор и сайт; показываются в диалоге «Сведения» |
| `help` | Имя markdown-файла справки; он ищется в `resource\<язык>\help\` папки плагина, затем в `resource\en\help\`. Кнопка «Справка» открывает его во встроенном просмотрщике |
| `resources` | Номер набора ключей `resource\<язык>\strings.json` плагина. Хост сверяет его с `"version"` в `locale.json` пакета: пакет новее плагина игнорируется, старее применяется (недостающие ключи остаются английскими). Без поля подходит любой пакет |
| `startup` | `true` – загрузить при запуске. Нужно плагину, чья работа сводится к перехватчикам команд, сочетаниям клавиш, подписям и сегментам статуса: ленивая загрузка по схеме или расширению его не запустит |
| `permissions` | Права, которые плагин просит разрешить пользователю: `["vfs.read"]`. Без разрешения (кнопка «Разрешения...» в списке плагинов) вызовы, которым оно нужно, отклоняются, см. §2.6 |

Без `plugin.json` плагин тоже загружается (лениво – при открытии верхнего меню или списка плагинов).

## 2. Точки расширения

Нативный плагин экспортирует `mtn_plugin_get_abi_version`, `mtn_plugin_init(PHostApiTable)` и `mtn_plugin_shutdown`. Таблица `THostApiTable` (`uPluginHostAbi.pas`) растёт только в конце; поля ABI 2 и 3 нужно проверять на `Assigned`, если плагин должен работать и на более старом хосте. WASM-плагин пользуется теми же возможностями через импорты модуля `mtn_host` (список в заголовке `uWasmPluginHost.pas`). Все вызовы идут из главного потока, кроме `post_to_main`, `vfs_size`, `vfs_read_at` и `vfs_close`.

| Возможность | Нативный ABI | WASM-импорт | Что получает плагин |
|---|---|---|---|
| Схема VFS | `RegisterVfsScheme` | `register_vfs_scheme` | Свою схему URI: листинг, чтение, копирование |
| Подписи F-клавиш для схемы | `SetPanelFBar` (ABI 4) | – | `SetPanelFBar(plugin_id, scheme, json)`: пока панель показывает папку этой схемы, строка F-клавиш берёт подписи из JSON `{"root": {"F7": "New"}, "inside": {"Shift+F4": "X"}}` (`root` – корень `scheme:///`, `inside` – остальные папки; пустая подпись оставляет только номер). Пустой JSON снимает подписи. Только нативный плагин |
| Схема VFS с прогрессом и отменой | `RegisterVfsSchemeV2` (ABI 4) | – | То же, с таблицей версии 2: контекст операции (прогресс, отмена, текст ошибки), постраничный листинг, повтор с большим буфером, флаги копирования. Только нативный плагин, см. §2.8 |
| Панель для схемы | `RegisterPanelPlugin` | `register_panel_plugin` | Идентификацию панели схемы |
| Пункт меню | `RegisterMenuItem` | `register_menu_item` | Пункт в категории верхнего меню |
| Сочетание клавиш | `RegisterKeyBinding` | `register_key_binding` | Перебиндинг встроенного действия или сочетание для своей команды |
| Событие / перерисовка | `HostPublish`, `HostInvalidate` | `publish` | Шину событий |
| Своя команда | `RegisterCommand`, `ExecuteCommand` | `register_command`, `execute_command` | Команду с произвольным id (не совпадающим с именем встроенной) |
| Перехватчик встроенной команды | `RegisterCommandHook` | `register_command_hook` | Вызов до встроенной команды; ответ 1 отменяет её |
| Открытие файлов | `RegisterDocumentProvider` | `register_document_provider` | Решение по F3 / F4 для своих расширений: открыть самому, подсунуть другой URI (только нативный), пропустить |
| Запуск программой системы | `OpenExternal` | – | Открытие локального файла ассоциированной программой (только нативный) |
| Диалог | `ShowDialog` | `show_dialog` | Одноразовый модальный диалог по JSON-описанию; вместо текста JSON можно передать имя файла из `plugins\<id>\dialogs\<имя>.json` |
| Активация строки панели | `RegisterPanelActivate` | `register_panel_activate` | Реакцию на Enter / двойной щелчок по строке панели своей схемы |
| Подпись команды | `SetCommandCaption` | `set_command_caption` | Подпись в нижней строке клавиш |
| Текст в статусе | `SetStatusSegment` | `set_status_segment` | Именованный сегмент строки состояния панелей |
| Цветной текст в статусе | `SetStatusSegmentStyled` | – (только нативные плагины) | Тот же сегмент из цветных частей: JSON-массив `[{"t": "текст", "role": "ok", "fg": "#RRGGBB", "bg": "#RRGGBB", "b": true}]`; `role` – `ok`, `warn`, `error`, `info`, `accent`, `neutral` (пара цветов, читаемая в любой теме), `fg` и `bg` переопределяют её цвета, часть без цветов берёт цвета строки состояния |
| Настройки | `RegisterSettings`, `GetSetting`, `SetSetting` | `register_settings`, `get_setting`, `set_setting` | Обработчик кнопки «Настройки» в диалоге плагинов и своё хранилище «ключ – значение» |
| Документ | `DocInfo`, `DocGetText`, `DocReplace`, `DocSetCursor` | `doc_info`, `doc_get_text`, `doc_replace`, `doc_set_cursor` | Текст документа, открытого в просмотрщике или редакторе: описание, выделение, строка, весь текст; замена одним шагом отмены |
| Панели | `PanelInfo`, `PanelGoto`, `PanelRefresh` | `panel_info`, `panel_goto`, `panel_refresh` | Обе панели (папка, строка под курсором, выбранные строки), показ папки в панели, обновление |
| Буфер обмена | `ClipboardGet`, `ClipboardSet` | `clipboard_get`, `clipboard_set` | Текст в системном буфере обмена |
| Уведомление | `ShowMessage` | `show_message` | Короткое уведомление (всплывающая плашка) |
| События хоста | `Subscribe` | `subscribe` | События `doc.opened`, `doc.saved`, `doc.closed`, `language.changed` |
| Сведения о программе | `HostInfo` | `host_info` | Версию и язык интерфейса (JSON) |
| Перевод текстов | `Translate` (ABI 3) | `translate` | Текст по ключу из пакета `resource\<язык>\strings.json` плагина или английский вариант по умолчанию, см. §2.7 |
| Пункт списка дисков | `RegisterDriveItem` (ABI 4) | – | Пункт в окне выбора диска (Alt+F1 / Alt+F2) и в полосе дисков: подпись, адрес, который открывается по Enter, приоритет. Пункты идут после встроенных и получают цифры 5–9 (не больше пяти от всех плагинов); пока панель стоит на адресе той же схемы, пункт отмечен. Выгрузка плагина убирает пункты. Только нативный плагин |
| Поверхность для картинки | `SurfaceOpen`, `SurfaceSetFrame`, `SurfaceSetInfo`, `SurfaceSetTimer`, `SurfaceClose` | `surface_open`, `surface_set_frame`, `surface_set_info`, `surface_set_timer`, `surface_close` | Вкладку просмотра, в которой хост рисует кадры (пиксели BGRA) плагина; клавиши, таймер и закрытие приходят обратно |

Имена встроенных команд для перехватчиков – имена действий раскладки (`Copy`, `Move`, `View`, `Edit`, `Delete`, `MkDir`, ...; полный список – `KEYMAP_ACTION_NAMES` в `uKeymap.pas`). Перехватчик вызывается для нажатия клавиши на панелях, для глобальных клавиш и для пункта верхнего меню; источник (`key` / `menu`) передаётся в вызов. В просмотрщике и редакторе перехватываются действия `DocViewEdit`, `DocClose`, `EditorSave` и остальные `Doc*` / `Editor*`.

Что плагин не получает: `TCanvas`, цвета, окна. Диалог, панель, строка клавиш и строка состояния рисуются хостом по логическим данным плагина; картинка или кадр видео попадают во вкладку просмотра через поверхность (раздел 2.4).

### 2.1. Минимальный нативный плагин

``pascal
library Hello;

uses uPluginHostAbi in '..\..\Core\uPluginHostAbi.pas';

function HookDelete(AUserData: Pointer; ACommand, AOrigin: PAnsiChar): Int64; cdecl;
begin
  Result := 0; // 1 = Delete handled by the plugin
end;

function mtn_plugin_get_abi_version: Int64; cdecl;
begin
  Result := cPluginAbiVersion;
end;

function mtn_plugin_init(AHostApi: PHostApiTable): Int64; cdecl;
begin
  if Assigned(AHostApi.RegisterCommandHook) then
    AHostApi.RegisterCommandHook('mtn.hello', 'Delete', @HookDelete, nil, 100);
  Result := 0;
end;

procedure mtn_plugin_shutdown; cdecl;
begin
end;

exports mtn_plugin_get_abi_version, mtn_plugin_init, mtn_plugin_shutdown;

begin
end.
``

Манифест такого плагина – `{"id":"mtn.hello","abi":2,"startup":true}`.

### 2.2. Минимальный WASM-плагин

``wat
(module
  (import "mtn_host" "register_command_hook"
    (func $hook (param i32 i32 i32 i32 i32) (result i32)))
  (memory (export "memory") 1)
  (data (i32.const 16) "Delete")
  (data (i32.const 32) "on_delete")
  (func (export "mtn_plugin_get_abi_version") (result i64) (i64.const 2))
  (func (export "mtn_plugin_init") (result i32)
    (drop (call $hook (i32.const 16) (i32.const 6) (i32.const 32) (i32.const 9) (i32.const 100)))
    (i32.const 0))
  (func (export "mtn_plugin_shutdown"))
  (func (export "on_delete") (result i32) (i32.const 0)))
``

Готовый проект на Rust с таким же устройством – `samples/plugins/mtn.template.rs`: копия каталога, новый `id` в `plugin.json` и своя команда вместо `on_count` дают рабочий плагин.

Гость не видит память хоста и не может запускать программы: хост копирует строки в линейную память гостя и обратно. WASI подключается только по `"wasi": true` и пустым: ни файлов, ни окружения, ни сети.

Модуль, чья среда выполнения занимает всю линейную память (Go), экспортирует `mtn_scratch_ptr() -> i32` – адрес своего 32-килобайтного буфера для обмена строками с хостом; без этого экспорта хост использует хвост памяти гостя.

### 2.3. Настройки плагина

Плагин с настройками регистрирует обработчик (`RegisterSettings` / `register_settings`). В **Параметры → Плагины...** такая строка помечена `[settings]`, и кнопка «Настройки» вызывает обработчик: он показывает диалог плагина (`ShowDialog`) и сохраняет выбор. Значения плагин хранит через `SetSetting` / `GetSetting` (строки «ключ – значение»): хост записывает их в `plugin-settings-<id>.json` в папке настроек, поэтому они попадают в экспорт и импорт настроек и работают в переносном режиме; плагину путь к файлу не нужен. `GetSetting` возвращает длину значения, `-1` – ключ не задан, `-2` – буфер мал. Образцы: `mtn.demo.pas` (файл заметок) и `mtn.demo.go` (ширина отступа).

### 2.4. Поверхность для картинок и видео

Плагин не рисует сам: он открывает вкладку просмотра и отдаёт хосту пиксели, а хост вписывает кадр в вкладку по центру (тот же проход рисования, что у картинок Quick View). Заголовок вкладки, подсказка клавиш и строка состояния остаются родными.

1. `SurfaceOpen(plugin_id, title, on_key, on_tick, on_closed, user)` открывает вкладку и возвращает дескриптор (больше 0); `-1` – вкладку открыть нельзя (хост не над панелями). Любой из обратных вызовов может быть пустым. Обычно вызывается из провайдера открытия (F3), который затем отвечает «обработано».
2. `SurfaceSetFrame(handle, width, height, pixels, length)` заменяет картинку: `width x height` точек по 4 байта в порядке B, G, R, A, строки сверху вниз без выравнивания, `length = width * height * 4`. Хост копирует данные, поэтому буфер можно переиспользовать. Сторона – не больше 16384, объём – не больше 256 МБ. Кадр можно подменять сколько угодно раз.
3. `SurfaceSetInfo(handle, title, status)` задаёт заголовок вкладки и текст строки состояния (размер, номер, время).
4. `SurfaceSetTimer(handle, interval_ms)` включает таймер хоста: `on_tick` вызывается каждые `interval_ms` миллисекунд, пока вкладка на экране (скрытая вкладка таймер не получает). Так плеер выбирает следующий кадр; `0` выключает таймер.
5. `on_key(user, key)` получает нажатие, названное как `Left`, `Right`, `Up`, `Down`, `Home`, `End`, `PageUp`, `PageDown`, `Enter`, `Space`, `Tab`, `Esc`, `Backspace`, `Delete`, `Insert`, `F1`..`F12`, символ (`a`, `+`) или с префиксами `Ctrl+`, `Alt+`, `Shift+` (`Ctrl+C`); ответ 1 – клавиша использована. Esc и F10 тоже приходят в `on_key` до встроенной обработки: если плагин ответил 1, хост ничего не делает (плагин сам вызывает `surface_close` или меняет режим), иначе Esc выходит из полного экрана, а при выключенном – закрывает вкладку, F10 закрывает вкладку. Закрытие вкладки мышью, Ctrl+F4 и выгрузка плагина не зависят от ответа.
6. `on_closed(user)` вызывается, когда вкладку закрыл пользователь; плагин освобождает декодер. Если вкладку закрыл сам плагин (`SurfaceClose`) или плагин выгружен, вызова нет: после выгрузки хост закрывает вкладки плагина и больше не вызывает его.

Всё выполняется в главном потоке: долгое декодирование в обработчике задерживает интерфейс, поэтому тяжёлые файлы стоит уменьшать до разумного размера до `SurfaceSetFrame`. Образцы: `mtn.demo.img` (Rust, масштаб колесом, перетаскивание, поворот, полный экран, показ в панели) и `mtn.demo.video` (C++, видео и звук на Media Foundation, пауза и перемотка).

**Режимы, мышь и своё окно.** `SurfaceOpenEx(plugin_id, title, mode, on_key, on_tick, on_closed, on_mouse, user)` открывает поверхность в одном из режимов: `0` – вкладка, `1` – вкладка на весь экран без рамки и строк клавиш, `2` – панель напротив активной (как Quick View; закрывается тем же сочетанием, повторный вызов заменяет содержимое). Добавьте `256`, чтобы вместо кадров получить собственное окно (см. ниже). `SurfaceSetFullscreen(handle, on)` переключает полный экран, а `surface_get_fullscreen(handle)` возвращает его состояние (`1` – включён, `0` – нет, `-1` – неизвестный дескриптор); если плагин не занял Esc, он сначала выходит из полного экрана и только вторым нажатием закрывает вкладку.

`on_mouse(user, kind, x, y, width, height, button, extra, shift)`: `kind` 0 – кнопка нажата, 1 – отпущена, 2 – движение с нажатой кнопкой, 3 – колесо (`extra` – число щелчков, положительное – от пользователя), 4 – двойной щелчок, 5 – размер области изменился (`width`, `height`; приходит и до первого кадра, по нему плагин готовит кадр нужного размера). `x`, `y` – в пикселях от левого верхнего угла области; `button` 1 – левая, 2 – правая, 3 – средняя; `shift` – биты 1 Shift, 2 Ctrl, 4 Alt. Ответ 1 – событие использовано.

**Собственное окно.** Для режима `+256` хост создаёт дочернее окно-контейнер над областью поверхности, а `SurfaceNativeHandle(handle)` возвращает его HWND. Плагин создаёт внутри него свои окна (проигрыватель, веб-вид, элемент управления); хост растягивает их на весь контейнер, держит над областью вкладки и прячет под диалогами и меню. Окна плагина разрушаются вместе с контейнером при закрытии вкладки. Для WASM-плагина собственное окно недоступно. Образец – `mtn.demo.nativeview`. WASM-плагин использует те же функции в модуле `mtn_host` (сигнатуры – в шапке `uWasmPluginHost.pas`): обработчики задаются именами экспортов, пиксели читаются из памяти гостя.

### 2.5. Документы, панели и буфер обмена

Плагин может работать с тем, что открыто в программе, и менять встроенное поведение просмотрщика и редактора. Всё выполняется в главном потоке.

**Документ.** Вызовы относятся к документу активной вкладки (F3 или F4); без текстового документа на экране (панели, вкладка с картинкой, шестнадцатеричный вид) они возвращают `-1`.

* `doc_info` – JSON: `uri`, `path`, `viewOnly`, `canEdit`, `hex`, `markdown`, `dirty`, `lines`, `row`, `col` (с нуля), `hasSelection`.
* `doc_get_text(what)` – текст: `what` 0 – выделение (пустая строка, если ничего не выделено), 1 – весь документ (строки через LF), 2 – строка с курсором.
* `doc_replace(what, text)` – заменяет тот же текст одним шагом отмены. `what` 0 при пустом выделении вставляет текст в позицию курсора. В просмотрщике (только чтение) вернёт `-1`: плагин может предложить нажать F4.
* `doc_set_cursor(row, col)` – курсор; позиция за концом приводится к границам текста.
* `doc_set_selection(row1, col1, row2, col2)` – выделение от первой позиции ко второй, курсор уходит в конец.
* `doc_line(index, buf, size)` – текст одной строки (с нуля) без перевода строки; `-1` – такой строки нет.

**Как вернуть текст.** `host_info`, `translate`, `doc_info`, `doc_get_text`, `panel_info` и `clipboard_get` возвращают длину текста в байтах UTF-8. Текст (и нулевой байт в нативном API) записывается в буфер, только если он помещается, поэтому результат, не меньший размера буфера, значит «повторите с буфером побольше» (`NULL` – только измерить). В WASM нулевой байт не пишется, текст помещается при `длина <= размер`. `-1` – данные недоступны.

**Панели.** `panel_info` – JSON: `active` (`left` или `right`) и для каждой стороны `uri` папки, `cursor` (URI строки под курсором, если это не `..`), `cursorIsDirectory` и `selected` (URI выбранных строк). `panel_goto(side, uri)` показывает папку в панели: `side` 0 – левая, 1 – правая, -1 – активная; фокус остаётся на прежней панели. Вызов не выполняется, если открыт диалог или активна не вкладка с панелями. `panel_refresh` перечитывает активную панель. URI файлов имеют вид `file:///C:/dir/a%20b.txt` (проценты – кодировка UTF-8).

* `panel_list(side, buf, size)` – JSON одной панели: `uri` папки, `cursor` (индекс в `rows`) и `rows` – строки `{uri, name, dir, size}`. Служебная строка `..` не входит.
* `panel_set_cursor(side, uri)` ставит курсор на строку; если строка в другой папке, панель сначала переходит туда.
* `panel_select(side, mode, arg)`: `mode` 0 – выбрать файлы по маске `arg` (`*.txt`), 1 – снять выбор по маске, 2 – снять весь выбор, 3 – выбрать строку `arg` (URI), 4 – снять выбор с неё.

**Буфер обмена и уведомления.** `clipboard_get` / `clipboard_set` читают и пишут простой текст. `show_message(text, kind)` показывает всплывающее уведомление (0 – сведения, 1 – предупреждение).

**События.** `subscribe(topic, ...)` подписывает на события хоста: `doc.opened` (текст открыт и загружен), `doc.saved` (сохранение закончилось успешно), `doc.closed`; `doc.changed` (текст изменён; приходит не чаще раза за проход цикла сообщений), `panel.dir` (панель сменила папку: `{"side": "left", "uri": "..."}`) и `panel.cursor` (курсор панели на новой строке: `{"side": "left", "uri": "..."}`); полезная нагрузка документных событий – JSON `{"uri": "..."}`; тема `*` – все события. Подписка плагина на тему одна: повторный вызов заменяет обратный вызов. После выгрузки плагина события ему не приходят.

**Фоновые задачи и ход выполнения.** Функции хоста вызываются только из главного потока, кроме одной: `post_to_main(plugin_id, cb, user)` можно вызывать из любого потока, `cb` выполнится в главном потоке на ближайшем проходе цикла сообщений. Так фоновый поток плагина передаёт результат интерфейсу. `progress_set(plugin_id, id, text, percent)` показывает уведомление, которое остаётся на экране и обновляется по `id`, пока его не уберёт `progress_end(plugin_id, id)`; `percent` меньше 0 – без процентов. После выгрузки плагина вызовы из его потоков отбрасываются. Образец – `mtn.demo.panelkit` (Ctrl+Shift+K считает файлы и размер папки в фоне).

**Подсветка текста.** `register_highlighter(plugin_id, extensions, cb, user)` раскрашивает файлы с перечисленными расширениями (`".json;.ini"`) в просмотрщике и редакторе. `cb(user, line, spans, cap)` получает строку в UTF-8 и записывает до `cap` отрезков по три `int32` (начало в байтах, длина в байтах, класс), возвращает их число. Классы: 0 обычный, 1 комментарий, 2 строка, 3 число, 4 ключевое слово, 5 тип, 6 функция, 7 оператор, 8 препроцессор, 9 константа, 10 ключ, 11 ошибка. Хост сам переводит байты в символы, подбирает цвета под фон темы и кэширует ответы по тексту строки; у плагина один раскрасчик, повторный вызов заменяет прежний. Раскраска строки не зависит от соседних, и многострочные конструкции плагин не видит. Образец – `mtn.demo.highlight`.

**Подсветка с состоянием (WASM).** Многострочные комментарии и строки требуют знать, чем закончилась предыдущая строка. `register_highlighter_state(ext_ptr, ext_len, export_ptr, export_len, lang)` регистрирует такой раскрасчик для одного языка; плагин вызывает его по разу на язык, `lang` хост возвращает в вызове без изменений, а повторная регистрация тех же расширений заменяет прежнюю. Экспорт гостя `(line_ptr, line_len, lang, state_in, out_ptr, out_cap) -> i32` получает строку в UTF-8 и состояние в начале строки: 0 в начале файла, иначе число, которое сам плагин вернул для предыдущей строки. По адресу `out_ptr` он пишет состояние на конце строки (`i32`), затем до `out_cap` отрезков по три `i32`, как выше, и возвращает число отрезков, а `-1`, если не знает `state_in` (хост начинает файл заново). Состояние – непрозрачное число плагина: один и тот же снимок разбора должен всегда получать одно и то же число, пока он жив, тогда равные состояния равны и для хоста. Хост хранит состояние в начале каждой строки открытого текста, при правке сбрасывает состояния от изменённой строки и досчитывает их по мере прорисовки, не дольше 30 мс за кадр; ответы кэшируются по паре «состояние, строка». Строки длиннее 3500 байт остаются без цвета и состояние не меняют; в потоковом просмотре (файлы больше 10 МБ) строки красятся с состоянием 0. Расширения могут быть и именем файла целиком (`Makefile`). Лимит топлива на один вызов выше обычного, потому что первый разбор языка компилирует его регулярные выражения. Образец – `mtn.highlight` (Rust, крейт `syntect`).

**Файловая система (чтение).** `vfs_list(plugin_id, uri, cb, user)`, `vfs_exists(...)` и `vfs_read(plugin_id, uri, max_bytes, cb, user)` читают через те же схемы, что и сама программа: `file:///`, архивы (`...zip!/...`), `sftp://`, схемы других плагинов. Вызовы асинхронные: каждый возвращает `0` (задание запущено, обратный вызов придёт ровно один раз), `-1` (неверные аргументы) или `-2` (у плагина нет права `vfs.read`, обратного вызова не будет). Обратный вызов выполняется в главном потоке на одном из ближайших проходов цикла сообщений, никогда изнутри самого вызова; плагин, выгруженный до ответа, его не получает. `status` в обратном вызове: 0 – готово, 1 – не найдено, 2 – доступ запрещён, 3 – не поддерживается или файл больше `max_bytes`, 4 – отменено, 5 – ошибка ввода-вывода, 6 – неверный URI. Результат `vfs_list` – JSON `{"uri": "...", "entries": [{"name", "uri", "dir", "size", "modified"}]}` (`modified` – секунды с 1970 года по местному времени, не больше 100 000 записей); `vfs_exists` – `{"exists": true, "dir": false}`; `vfs_read` отдаёт содержимое файла целиком (`max_bytes` 0 – 2 МБ, не больше 64 МБ). Данные в обратном вызове действительны только на время вызова. В WASM функции вызываются так: `vfs_list(uri_ptr, uri_len, export_ptr, export_len)`, `vfs_exists(...)` и `vfs_read(uri_ptr, uri_len, max_bytes, export_ptr, export_len)` возвращают дескриптор (больше 0), экспорт гостя `(handle, status)` вызывается по окончании, после чего `vfs_result(handle, out_ptr, out_cap)` отдаёт результат: длину в байтах, причём данные копируются, только если `длина <= out_cap`, и тогда дескриптор освобождается; результат длиннее буфера остаётся для повторного вызова. Образец – `mtn.demo.panelkit` (Ctrl+Shift+L показывает размер и первую строку файла под курсором, в том числе внутри архива).

**Чтение файла по частям.** Файл больше 64 МБ или такой, который нужно читать кусками (видео из архива или с sftp), открывается через `vfs_open(plugin_id, uri, cb, user)`; право то же, `vfs.read`. Вызов возвращает номер задания (больше 0; обратный вызов `cb(user, status, handle)` придёт в главном потоке), либо `-1`, `-2` или `-3` (у плагина уже открыто или открывается 16 файлов). Пока файл не открыт, задание можно отменить: `vfs_cancel(job)` возвращает `0` (отменено) или `-1` (задания нет, оно уже закончилось или чужое), а обратный вызов всё равно придёт один раз со статусом 4. Отмена нужна прежде всего для файлов, которые копируются во временный файл. Локальный файл открывается на месте. Любой другой URI (архив, `sftp://`, схема плагина) хост сначала копирует во временный файл и, если копирование занимает больше полусекунды, показывает уведомление с ходом копирования; временная копия удаляется при закрытии. Дальше работают три вызова, которые можно вызывать **из любого потока**, как `post_to_main`: `vfs_size(handle)` – размер в байтах (`-1`, если дескриптор неизвестен); `vfs_read_at(handle, offset, buf, size)` – читает до `size` байт с позиции `offset` и возвращает число прочитанных байт, `0` в конце файла, отрицательное число при ошибке (блокирует только вызвавший поток, главный не затрагивается); `vfs_close(handle)` – закрывает файл (`0` – закрыт, `-1` – неизвестный дескриптор), чтение в другом потоке сначала завершается. Дескриптор другого плагина WASM-хост отвергает; незакрытые файлы хост закрывает при выгрузке плагина. В WASM: `vfs_open(uri_ptr, uri_len, export_ptr, export_len)` возвращает номер задания, экспорт гостя `(job, status, file)` вызывается по окончании, `file` – дескриптор; `vfs_cancel(job)`; `vfs_size(file)` и `vfs_read_at(file, offset_i64, out_ptr, out_cap)` возвращают `i64`, за один вызов читается не больше 16 МиБ; `vfs_close(file)`. WASM-плагин вызывает их только из главного потока.

**Замена встроенных функций редактора.** Перехватчик действия `EditorSave`, `DocClose`, `DocViewEdit` и других (раздел 2) вместе с вызовами документа позволяет менять работу встроенной команды: перехватчик `EditorSave` может привести текст к нужному виду (убрать пробелы в конце строк, добавить перевод строки) и вернуть 0, после чего сохранение продолжается уже с новым текстом; ответ 1 отменяет сохранение. Образец – `mtn.demo.texttools`.

**Сочетания клавиш.** Для своих команд берите клавиши F1–F12 с модификаторами или `Ctrl+Shift+буква`. `Ctrl+Alt+буква` в текстовых полях (редактор, командная строка) воспринимается как ввод символа раскладки (AltGr) и до команды плагина не доходит; сочетание, которое уже занято встроенным действием, остаётся за ним.

### 2.6. Права плагина

Часть вызовов хоста требует разрешения. Плагин называет нужные права в манифесте (`"permissions": ["vfs.read"]`), а пользователь разрешает их в **Параметры → Плагины...**: кнопка «Разрешения...» открывает диалог с флажками для каждого права плагина (и для замены встроенных обработчиков, если плагин её просит). Состояние запоминается в `plugin-permissions.json` в папке настроек, в строке плагина оно видно как `[needs vfs.read: on]` или `[needs vfs.read: off]`, а в «Сведениях» перечислено словами. Вызов, которому нужно право, отклоняется, пока оно не названо в манифесте и не разрешено пользователем; плагин получает отказ (`-2` у файловых вызовов) и может объяснить, что делать.

| Право | Что открывает |
|---|---|
| `vfs.read` | `vfs_list`, `vfs_exists`, `vfs_read`, `vfs_open`, `vfs_cancel`, `vfs_size`, `vfs_read_at`, `vfs_close`: просмотр папок и чтение файлов на любом диске, в архиве, на sftp |

Остальные вызовы хоста (документ, панели, буфер обмена, поверхности, подсветка) права не требуют. Проверка опирается на идентификатор плагина, который плагин сам передаёт в вызове; нативная DLL работает в процессе программы с её правами, поэтому права удерживают честный плагин в заявленных рамках и показывают пользователю, чего он хочет, но не изолируют враждебный код. Единственный надёжный предел – WASM-плагин: у него нет другого пути к хосту, кроме импортов `mtn_host`.

### 2.7. Языки плагина

Язык интерфейса задаёт хост; плагин его не выбирает. Текущий язык – поле `language` ответа `host_info` (`en`, `ru`, `de`, ...); папка настроек программы – поле `configDir` того же ответа; при смене языка хост публикует событие `language.changed` с JSON `{"language":"ru"}` (подписка через `Subscribe` / `subscribe`), и плагин может перестроить уже показанные подписи.

Тексты плагина по-английски лежат в самом коде, переводы – в пакетах рядом с плагином:

```
plugins\<id>\resource\<язык>\locale.json    {"version": N, "name": "Русский"}
plugins\<id>\resource\<язык>\strings.json   ключ -> текст (вложенные объекты читаются как ключи через точку)
plugins\<id>\resource\<язык>\help\<файл из "help">
```

Перевод плагин получает у хоста: `Translate(plugin_id, key, default, buf, size)` в нативном ABI 3 или `translate(key_ptr, key_len, def_ptr, def_len, out_ptr, out_cap)` в WASM. Результат – текст из `strings.json` для текущего языка либо `default`, если язык английский, пакета или ключа нет. Текстовый результат возвращается так же, как у `host_info`. Поле `Translate` есть только в ABI 3: на более старом хосте его нужно проверять на `Assigned`.

Версия пакета. Поле манифеста `resources` – номер набора ключей, под который написан плагин; `version` в `locale.json` пакета сверяется с ним. Совпадает – пакет применяется; старее – применяется, недостающие ключи остаются английскими; новее плагина или нет `locale.json` – пакет игнорируется. Без `resources` подходит любой пакет. Новый язык добавляется копированием папки `resource\<язык>\` в папку плагина без пересборки.
### 2.8. Схема VFS версии 2

`RegisterVfsSchemeV2(plugin_id, scheme, callbacks, user_data, priority)` принимает `TVfsCallbacksCdeclV2` (`uPluginHostAbi.pas`). Вызовы синхронные и идут в рабочем потоке хоста; один вызов не блокирует другие, поэтому плагин защищает своё состояние сам.

Каждому вызову хост передаёт контекст операции `PVfsOpContext`, действительный до возврата из вызова:

| Поле | Что делает |
|---|---|
| `ReportProgress(ctx, done, total, item_done, item_total, name)` | Ход операции: `done`/`total` – вся операция (`total` 0 – размер неизвестен), `item_*` – текущий файл, `name` – его имя. Хост показывает ход в окне задания и не чаще раза в 80 мс. Возвращает 1, если пользователь отменил операцию |
| `IsCancelled(ctx)` | 1 – пользователь отменил; плагин прекращает работу и возвращает `verCancelled` |
| `SetErrorText(ctx, text)` | Текст (UTF-8), который хост покажет вместе с ошибкой вместо стандартного |

Особенности таблицы версии 2:

* `ListDirectory(uri, user, ctx, offset, buf, size, &negotiated, &more)` возвращает записи с номера `offset` (JSON-массив, как в версии 1) и ставит `more` = 1, пока записи остались. Хост вызывает его снова с `offset`, увеличенным на число принятых записей; плагин держит список на время одной операции. Запись может содержать `unixMode` (права файла, например 493 для 0755).
* Если результат не поместился в буфер (4 МБ), плагин возвращает `verNeedsBiggerBuffer` и в `negotiated` нужный размер; хост повторяет вызов с буфером такого размера (до 256 МБ).
* `CopyItem` / `MoveItem` получают `flags`: бит 0 – перезаписывать, бит 1 – сохранять время. Одна сторона копирования всегда локальный `file://`-путь, если обе стороны не принадлежат этому плагину. Папки плагин копирует целиком, когда пишет в свою схему; при чтении из неё хост обходит дерево сам и вызывает `CopyItem` на каждый файл. Копирование и перемещение между разными плагинами или плагином и `sftp://` хост выполняет через временную локальную копию; перемещение между плагином и локальной папкой – копирование и удаление источника.
* Коды результата: к кодам версии 1 добавлены `verCancelled` (8), `verAuthFailed` (9, "доступ запрещён" с текстом плагина) и `verTimeout` (10, ошибка ввода-вывода).

**Адреса.** Схема, которую хост не знает сам, считается деревом папок вида `схема://узел/путь`: путь POSIX, без процентного кодирования, пустой узел (`схема:///`) – корень схемы. Родитель `схема://узел/` – `схема:///`, у корня родителя нет. Так плагин получает переход вверх, сравнение адресов и заголовок вкладки без собственного кода. Адреса со вложенным архивом (`!/`) подчиняются правилам архивов.

## 3. Замена встроенного обработчика

Реестр VFS сортирует обработчики по приоритету (меньше – раньше). Плагин без разрешения всегда получает приоритет не ниже 60 и поэтому не обгоняет встроенные: `find` (10), `sys` / `recycle` / `ws` / `sftp` (15), цепочку `!/` zip (20), расширения `.zip` / `.jar` / `.apk` (50). Схемы `file`, `sys`, `recycle`, `find` и `ws` заменить нельзя вообще.

Чтобы заменить `sftp://` или Enter на `.zip`:

1. Плагин перечисляет ключи в `overrides` манифеста и регистрирует схему (для архивного расширения – ещё и `archiveExtensions`).
2. Пользователь разрешает замену в **Параметры → Плагины...** (кнопка «Разрешения...», флажок замены; строка плагина помечена `[replaces ...: on]`) или вносит идентификатор плагина в `plugins\overrides.json` вручную:

``json
{ "allow": ["mtn.example"] }
``

3. После перезапуска плагин загружается при старте, его записи получают приоритет не выше 5, и встроенный обработчик уступает. Выгрузка плагина снимает разрешение и возвращает встроенный обработчик.

Пример из поставки: `mtn.7z` объявляет `"overrides": [".zip"]` и расширение `zip`. По умолчанию `.zip` открывает встроенный модуль; после `{"allow": ["mtn.7z"]}` Enter на `.zip` ведёт на `7z:///<путь>!/` и архив обслуживает `7z.dll` (шифрованные архивы AES, редкие методы сжатия). Замена касается перехода по Enter: пути вида `file:///x.zip!/` (Ctrl+PgDn, docx и подобные) по-прежнему обслуживает встроенный zip.

## 4. Отключение плагина

В **Параметры → Плагины...** каждый плагин помечен `[x]` (включён) или `[ ]` (выключен). Пробел на строке включает и выключает плагин; выбор применяется по кнопке «ОК» (плагин выгружается или загружается), а «Отмена» его отбрасывает. Выбор хранится в `disabled-plugins.json` в папке настроек. Выключенный плагин не загружается ни при запуске, ни ленивыми триггерами.

Порядок в списке – порядок загрузки. Ctrl+Вверх и Ctrl+Вниз переставляют выбранный плагин; порядок хранится в `plugin-order.json` в папке настроек (плагины, которых в файле нет, идут после перечисленных, в порядке папок). Порядок важен, когда у нескольких плагинов одинаковый приоритет: перехватчик команды, провайдер открытия или обработчик схемы плагина, загруженного раньше, спрашивается раньше. Плагины, которые ещё не загружены, следуют новому порядку сразу; уже загруженные сохраняют свои регистрации до следующего запуска. Приоритет, который плагин называет при регистрации (`priority`), сильнее порядка загрузки.

Образцы на разных языках лежат в `samples\plugins` (см. §5); рабочий образец, который пользуется почти всеми точками расширения, – `src/tests/plugins/SamplePlugin.dpr`.

## 6. Надёжность

* Исключение в обработчике, перехватчике или провайдере считается отказом: встроенное поведение выполняется.
* Нативный плагин работает в процессе MTN2 и не изолирован; сбой в его коде может уронить приложение. WASM-плагин изолирован: ловушка, выход за память и нехватка топлива не затрагивают хост.
* При выгрузке хост снимает регистрации плагина (VFS, меню, команды, перехватчики, провайдеры, подписи, сегменты, ответы диалогов) до освобождения модуля.

## 7. Плагины сообщества

Список плагинов, которые написали не авторы MTN2. Реестра с установкой из интерфейса нет: плагин ставится копированием каталога `plugins\<id>\` рядом с программой, а вопросы к плагину идут к его автору.

| Плагин | Автор | Что делает | Вид | Ссылка |
|---|---|---|---|---|
| – | – | В списке пока нет плагинов | – | – |

Нативный плагин (DLL, `.so`) работает в процессе MTN2 с правами пользователя и не изолирован, поэтому ставьте такие плагины только от авторов, которым доверяете, и смотрите разрешения в **Параметры → Плагины...**. WASM-плагин изолирован: у него нет доступа к хосту, кроме импортов `mtn_host` и разрешённых прав.

Чтобы добавить плагин в список, откройте pull request со строкой в таблице. Нужны:

* публичный репозиторий с исходным кодом и лицензией;
* `plugin.json` с `id`, `abi`, описанием на английском и русском и справкой;
* сборка для платформ, которые плагин заявляет (DLL, `.so`, `.wasm`), и инструкция сборки;
* список прав из `permissions` и пояснение, зачем они нужны.

Строки без исходного кода, с неясной лицензией или с недокументированным доступом к сети в список не попадают. Проверка кода плагина сводится к беглому просмотру: гарантии безопасности список не даёт.
