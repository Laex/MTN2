Аудит от 2026-09-24 (коммит `2920e57`): чего не хватает MTN2 для ежедневной работы по сравнению с FAR / Total Commander / NDN. Составлен по коду и чек-листам этапов в [readme.md](SDS.md), без запуска приложения. Второй раздел — план реализации выбранных пунктов 1-го приоритета.

## 1. Аудит

- **Консоль и терминалы:** ConPTY-консоль, терминалы во вкладках.

### П.3 — Сортировка имён без учёта регистра для любых алфавитов

**Проблема (проверено):** `CompareNaturalText('Яблоко', 'абрикос') = -1`, `('а', 'А') = 32`, `('ёж', 'жа') > 0`. Причина: в `uVfsUtils.CompareNaturalText.CmpChars` для символов вне ASCII вызывается `CompareText` — он сворачивает регистр только у ASCII и сравнивает по кодам.

**Решение:**
1. `src/Core/uVfsUtils.pas`, `CmpChars`: для не-ASCII — `CompareText(string(A), string(B), TLocaleOptions.loUserLocale)`. На Windows это `CompareString` (без учёта регистра, «ё» рядом с «е»); на POSIX — ICU, так что путь к кроссплатформенности не закрывается. Цифровые участки и ASCII-ветку не трогать.
2. Проверить скорость: сортировка 10 000 имён не должна заметно замедлиться. Если замедлится — кэшировать `ToUpper` по символу или сравнивать не-ASCII участок строки целиком одним вызовом.

**Тест:** в `src/tests/vfs/TestVfsUtils.dpr` добавить случаи `'Яблоко' > 'абрикос'`, `'а' = 'А'`, `'ёж' < 'жа'`, `'file2' < 'file10'`, смешанные `'Отчёт 2'` / `'отчёт 10'`. Исходник теста сохранять в UTF-8 **с BOM**, иначе кириллица в литералах читается как ANSI.

**Живой прогон:** папка с `Яблоко.txt`, `абрикос.txt`, `Ёлка`, `ель`, `file2`, `file10` — порядок по имени и обратный.

**Затрагивает:** сортировку панелей (`uPanelColumns`), порядок листинга (`uFileVfs`), архивы (`uZipArchiveCache`).

**Статус: сделано (2026-09-24).**
- **Как устроено:** имя разбивается на участки; цифровые сравниваются как числа (как раньше), нецифровые — целиком через `CompareStringW(LOCALE_USER_DEFAULT, NORM_IGNORECASE or SORT_STRINGSORT)`. На других ОС — `CompareText(..., loUserLocale)`.
- **Почему не как в плане:** посимвольное «ASCII по кодам, остальное по языку» отброшено — такой порядок не транзитивен.
- **Изменения порядка:**
  - «ё» сравнивается как «е» (словарный порядок): «ёлка» < «ель» < «жук»;
  - знаки препинания теперь идут перед буквами и в ASCII-именах: `_build` раньше `A` (как в Проводнике);
  - дефис значим: `a-b` ≠ `ab`.
- **Скорость:** сортировка 10 000 имён — ~17 мс (было ~4 мс).
- **Тесты:** `TestVfsUtils.dpr` — кириллица, регистр, «ё», цифры внутри кириллических имён, одинаковый порядок при сортировке прямого и обратного списка.

### П.7 — История просмотренных и отредактированных файлов (Alt+F11)

**Поведение (как в FAR):** Alt+F11 открывает список последних файлов, сверху самые свежие; у каждой строки пометка режима (`П` просмотр / `Р` правка, в EN `V` / `E`) и полный путь.
- **Enter** — открыть в том же режиме, **F3** / **F4** — принудительно просмотр / правка.
- **Ctrl+Enter** — перейти к файлу в панели (папка + курсор на файле).
- **Del** — убрать из истории. Набор символов фильтрует список, как в Alt+F8.
- Позиция в файле восстанавливается сама (`uFilePositions`).

**Реализация:**
1. Новый модуль `src/Core/uFileHistory.pas` по образцу `uFolderHistory`: `FileHistoryPush(URI, AEdit)`, `FileHistoryGetItems`, `FileHistoryRemove`; файл `filehistory.json` в папке настроек (`uConfigLocation`), не больше 100 записей. Повторное открытие переносит запись наверх и обновляет режим.
2. Запись в историю — в `TDualPanelWindow.OpenDocument` (все F3/F4 проходят через него). Файлы справки не пишутся: справка открывает свой `TEditorWindow` мимо `OpenDocument`.
3. Диалог: контроллер `TFileHistoryDialogController` в `uDualPanelHistoryDialogs.pas` (рядом с историей папок и команд) плюс `dialogs/filehistory.json`, вид `hdkFileHistory` в `uDualPanelUiTypes`. Фильтр — как `TCmdHistoryDialogController.HandleFilterInput`.
4. Клавиша: `kaFileHistory` → Alt+F11 в `uKeymap` (сейчас свободна); пункт «История файлов» в меню **Commands**; подпись F-строки при Alt («11» на F-строке не отображается — только меню и справка).
5. Отсутствующий файл: строка серым, Enter — сообщение «файл не найден» и предложение убрать из истории.

**Тест:** `src/tools/TestFileHistory.dpr` — порядок, перенос наверх, ограничение 100, сохранение и загрузка, удаление.

**Живой прогон:** F3 на трёх файлах, F4 на одном → Alt+F11 → порядок и пометки; Enter открывает в том же режиме и на той же позиции; Ctrl+Enter переходит в панель; перезапуск приложения — история на месте.

### П.6 — Свойства Windows (Alt+Enter)

**Поведение:** Alt+Enter на элементе панели (или на выделенных) открывает стандартное окно «Свойства» Проводника. Только для локальных файлов (`file://`); для архивов, SFTP, `sys://`, `recycle://` — сообщение в строке статуса «Недоступно для …».

**Реализация:**
1. `src/Core/uShellAssoc.pas`: `ShellShowProperties(const APaths: TArray<string>; AOwner: HWND): Boolean`.
   - Один путь — `SHObjectProperties(AOwner, SHOP_FILEPATH, PChar(Path), nil)`.
   - Несколько путей в одной папке — `SHMultiFileProperties` с `IDataObject` из PIDL (`SHParseDisplayName` + `SHCreateDataObject`), тот же приём, что у `ShellShowContextMenu`.
   - Под `{$IFDEF MSWINDOWS}`, на остальных платформах — заглушка `False`, как у соседних функций.
2. `kaProperties` → Alt+Enter в `uKeymap`. Проверить, что Alt+Enter не перехватывают раньше: верхнее меню срабатывает на отпускание одиночного Alt, а для Alt+буква работает быстрый поиск. Пункт «Свойства...» — в меню **Files**.
3. HWND главной формы брать тем же путём, что и для контекстного меню (`uMainForm.ArmContextMenuHold` / `WindowHandleToPlatform`), через событие хоста `OnShowProperties`, чтобы `uDualPanelWindow` не зависел от FMX-формы.
4. Окно свойств немодальное и живёт в процессе Explorer-шелла: MTN2 не ждёт его закрытия. Изменения атрибутов подхватывает уже существующий `uDirWatch`.

**Тест:** модульный — только выбор путей (локальные / нелокальные URI, выделение или курсор); вызов шелла проверяется вживую.

**Живой прогон:** Alt+Enter на файле, на папке, на трёх выделенных файлах, на `..` (ничего не происходит), внутри zip (сообщение); после смены атрибута в «Свойствах» панель обновляется.

### П.5 — Даты файла в диалоге атрибутов (Ctrl+Shift+A)

**Поведение (как в FAR):** в диалоге три строки — «Создан», «Изменён», «Доступ» — с полями `дд.мм.гггг чч:мм:сс` (формат по локали: `FormatSettings`).
- **Одиночный файл:** поля заполнены текущими значениями.
- **Несколько файлов:** поле пустое, если значения у файлов различаются; пустое поле — «не менять».
- **Кнопки:** «Текущее время» — все три поля = сейчас; «Исходные» — вернуть прочитанные значения.
- Флажок «Обрабатывать вложенные папки» действует и на даты.

**Реализация:**
1. `src/Core/uWinFileAttr.pas`:
   - в `TFileAttrSnapshot`, `TFileAttrDialogState` и `TFileAttrPlan` добавить `Created`, `Modified`, `Accessed: TDateTime` и флаги «смешано» / «менять»;
   - чтение — `GetFileAttributesEx` (`WIN32_FILE_ATTRIBUTE_DATA`, уже в UTC → локальное);
   - запись — `CreateFile(FILE_WRITE_ATTRIBUTES, FILE_FLAG_BACKUP_SEMANTICS для папок)` + `SetFileTime`; нулевой `PFileTime` означает «не менять»;
   - `FileAttrPlanIsNoOp` учитывает даты.
2. Разбор ввода — чистая функция `TryParseFileDateTime(const S: string; out ADate: TDateTime): Boolean` (форматы с секундами и без, `дд.мм.гг`), чтобы её можно было покрыть тестом.
3. `src/dialogs/setattr.json`: высота диалога +4 строки, три `label` + `input` (`date_created`, `date_modified`, `date_accessed`) и кнопки `dates_now`, `dates_orig`. Перевод подписей — в `strings/*.json` (раздел `DIALOG_SETATTR`). Проверить раскладку в `DialogDesigner` и через `uDialogLocaleLayout` для русских подписей.
4. `src/Core/uDualPanelFileDialogs.pas`: `BeginSetAttributes` заполняет поля, `DispatchSetAttributesCommand` обрабатывает кнопки дат и проверяет ввод. Неверная дата — сообщение, диалог остаётся открытым, фокус на ошибочном поле.
5. Ошибки записи (нет прав, файл занят) идут в существующий отчёт `ApplyFileAttrRoots`.

**Тест:** `TryParseFileDateTime`, построение состояния для одного и нескольких файлов (совпадающие / разные даты), `FileAttrPlanIsNoOp` с датами; запись и чтение `SetFileTime` на временном файле и папке.

**Живой прогон:** изменить «Изменён» у файла → колонка даты в панели обновилась; несколько файлов с разными датами → пустые поля, изменить только «Создан»; папка с «вложенными»; файл только для чтения; неверная строка даты.

**Статус: сделано (2026-09-24), живой прогон в MTN2 не проводился.**
- **Чтение и запись:** `uWinFileAttr.pas` — `TFileAttrTimes`, `FormatFileAttrTime` / `TryParseFileAttrTime`, запись `ApplyFileTimes`. Перевод во время панели — `FileTimeToLocalFileTime` и обратно, как в `uFileVfs`; тест сверяет записанное с тем, что прочитает панель.
- **Поведение полей:** записываются только изменённые поля. Поле с исходным текстом не трогается, поэтому миллисекунды файла не теряются из-за округления до секунд в поле.

### П.2 — Quick View для текстовых файлов (Ctrl+Q)

### П.4 — Выделение различающихся файлов (Ctrl+Shift+C)

**Поведение (как «Сравнить папки» в FAR / TC):** сравниваются текущие списки обеих панелей, без обхода вложенных папок и без чтения файлов. Выделение на обеих панелях заменяется.
- Файл есть только на одной стороне — выделяется.
- Файл с тем же именем на обеих: выделяется более новый; время совпадает (допуск 2 с — FAT), а размер разный — выделяются оба.
- Папки: выделяются только отсутствующие на другой стороне.
- Имена сравниваются без учёта регистра; `..` пропускается.
- Итог — в окне сообщения: «Различий нет» или «Выделено: слева N, справа M».

Работает на любой VFS (архивы, SFTP, результаты поиска), потому что использует уже загруженные строки панелей.

**Реализация:** чистая функция `ComparePanelRows` в новом модуле `src/Core/uPanelCompare.pas`; `TDualPanelWindow.CompareFolders` применяет результат к вкладкам обеих панелей; действие `kaCompareFolders` → Ctrl+Shift+C, пункт **Commands → Compare folders**.

**Тест:** `TestPanelCompare.dpr` — уникальные, более новые, равные, одинаковое время и разный размер, допуск 2 с, папки, регистр, `..`.

**Статус: сделано (2026-09-25), живой прогон через меню.**

## 4. План: командная строка, история в фильтре и поиске, контрольные суммы

### Общий выпадающий список истории — `uHistoryPopup.pas`

Не диалог, а всплывающий список, привязанный к однострочному полю: рамка, строки, подсветка, полоса прокрутки — как у списка `dckDropDown`. Открывается над полем (если сверху не помещается — под ним). Клавиши: ↑ ↓ PgUp PgDn Home End, **Enter** — подставить в поле, **Del** — удалить из истории, **Esc** — закрыть; любая другая клавиша закрывает список и работает как обычно. Щелчок по строке — подставить; щелчок мимо — закрыть.

### П.1 — Командная строка

- **История списком:** в командной строке с фокусом **Ctrl+↓** / **Alt+↓** раскрывают список прошлых команд (новые сверху). Enter подставляет команду, не выполняя её; Del удаляет из истории.
- **Дополнение путей с диска по Tab:** если в слове под курсором есть `\`, `/` или `X:`, варианты берутся с диска (папка слова, относительная — от папки активной панели), а не из списка панели. Повторный Tab перебирает варианты, как сейчас. Без разделителя — как раньше, имена из панели.
- **Реализация:** `CmdLinePathCompletions` в `uDualPanelCmd.pas` (чистая функция); `TDualPanelCmdLineManager` — событие `OnGetBaseDir`, список истории; отрисовка и щелчки — в `TDualPanelWindow`.

### П.2 — История в живом фильтре и в поиске F7

- **Фильтр Ctrl+F:** Ctrl+↓ / Alt+↓ в поле фильтра раскрывают прошлые маски (`uDialogHistory`, ключ `livefilter`); маска записывается по Enter.
- **Поиск F7 в просмотрщике и редакторе:** то же в поле «Find:» строки статуса; ключ `editfind` — общий с полем «Найти» диалога замены.

### П.3 — Контрольные суммы

- **Клавиша:** **Ctrl+Alt+H** (Files → Checksums...) на выделенных файлах и папках (папки — рекурсивно) или на файле под курсором. Только файлы на диске.
- **Расчёт:** диалог выбора алгоритма (MD5, SHA-1, SHA-256, SHA-512; последний выбор запоминается), затем расчёт в фоне с заглушкой «n / N», Esc — отмена. Результат — список `хеш *имя` с кнопками «Копировать», «Сохранить» (файл `<имя>.<алг>` для одного файла, `checksums.<алг>` для нескольких — в папке панели) и «Закрыть».
- **Проверка:** если под курсором один файл `.md5` / `.sha1` / `.sha256` / `.sha512`, он проверяется: каждая строка — `OK`, `FAILED`, `MISSING`; итог в заголовке списка. Форматы строк: `хеш  имя`, `хеш *имя`, BSD `SHA256 (имя) = хеш`.
